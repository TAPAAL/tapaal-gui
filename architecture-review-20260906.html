seam

Deep query editing module

Problem
The query editing module is shallow: tree mutation, selection, conversion, undo, and control state share one 7,555-line Swing implementation, so query rules leak across the seam.
Solution
Deepen one query editing module that absorbs tree behavior and leaves Swing responsible for rendering and events.

Benefits

  • locality: tree rules concentrate
  • leverage: all query categories
  • tests cross one seam
  • Swing fixtures disappear

Deletion test: deleting this deep module would spread selection, conversion, undo, and valid-edit rules back through every event handler.

After · construction and copying deepen

Deep query configuration module

defaults · invariants · variants · complete copies · persistence mapping

callers cannot assemble partial query state

Problem
The query configuration module is shallow: its interface exposes nearly every field, and assembly, copying, conversion, loading, and saving must each remember the same state.
Solution
Deepen query configuration so defaults, invariants, complete copying, and persistence mapping stay together while timed, untimed, HyperLTL, and SMC variation remains internal.

Benefits

  • locality: fields move together
  • leverage: callers inherit defaults
  • round-trip tests gain depth
  • partial copies become impossible

Concrete signal: copy() assigns siphon-trap state from query-reduction state and leaves several query fields behind; no query-copy tests cover this seam.

Deletion test: deleting this deep module would force every creator, converter, and persistence adapter to reconstruct query defaults and invariants.

Top recommendation

Deepen query-tree editing

It targets the hottest file and the recent arithmetic, HyperLTL, selection, enabledness, and freeze fixes; one deep module would create the highest immediate locality and a test surface independent of Swing.
